# Tools

The server exposes 103 tools in 13 groups. 49 only read data;
the other 54 change something and are hidden by `--read-only`. Most tools that change data
need `confirm: true`, so your agent should ask you first.

Your agent only sees the tools your API key's scopes allow. Names use `_`, so `feeds.list` on the
REST docs is `feeds_list` here. Use a group name with `--tools` to expose only that group.

_Generated by `npm run tools:update`. Do not edit by hand._

| `feeds_refresh_history` | Read | Recent imports and refreshes of a feed, newest first: products fetched, new, updated, marked unavailable and removed, and any error. |
| `feeds_get_audit` | Read | The feed's saved audit: pass/fail counts per category and per check, worst first, with sample failing products. Pass category (and check) to page through the failing products. Run feeds.run_audit first if there is none or products changed. Needs read:products as well. |
| `feeds_run_audit` | Write | Audit every product in the feed now (as the app's Run audit) and save the result, then return the overview. Large feeds take a while. Needs read:products as well. |
| `feeds_get_history` | Read | What changed in a feed, newest first: product edits, AI optimisations, rule runs, imports and refreshes, exports, label and classification jobs, with who did it and the recorded details. Filter by operation (e.g. update, optimize, process, export) or date, or search. |

## Rules (`rules`)

| Tool | Access | What it does |
| --- | --- | --- |
| `rules_metadata` | Read | Discover everything needed to author a rule: supported operators, action types, known product attributes, value formats, logic/priority ranges and schedule frequencies. Call this before rules.create. |
| `rules_list` | Read | List transformation rules for the team, optionally filtered to one feed. |
| `rules_get` | Read | Get one transformation rule by ID. |
| `rules_create` | Write | Create a transformation rule. Provide either conditions (flat, with logic) or condition_groups (with group_logic). A rule with no feed_id is a team template that is never applied automatically — use rules.copy to put it on a feed. Optional schedule_* fields enable automatic re-application on a cron (feed-scoped rules only). Call rules.metadata first for the valid operators/actions/attributes. |
| `rules_update` | Write | Update an existing transformation rule (partial). enabled=false pauses the rule everywhere; schedule_enabled=false pauses only its cron. feed_id re-scopes the rule to another feed (null = team template). |
| `rules_delete` | Write | Delete a transformation rule by ID. |
| `rules_copy` | Write | Copy a rule onto one or more feeds under a new name. Pass target_feed_id for a single feed (returns the new rule) or target_feed_ids for many (returns { copied, failed } — each feed is independent, a duplicate name on one does not block the others). Use this to make a team template (feed_id = null) runnable, or to clone a rule across sibling/region feeds. Schedules are not copied. |
| `rules_preview` | Read | Preview the impact of rules on a feed without saving changes. By default runs the feed's saved rules (optionally narrowed by rule_ids) against every product in the feed. Pass `rule` to preview an unsaved rule before creating it: against the feed it runs inside the feed's saved rule chain (replacing `rule.id` when it edits a saved rule) and reports only the fields it writes, exactly as applying it once saved would. Pass `products` (max 500) to test against a small fixture instead of the feed (the rule is then evaluated on its own). Previewing against the feed's products also needs read:products (a products fixture does not). Products whose price was set by hand keep it; they are counted in summary.manualPriceSkippedCount. Response: summary counts for the whole feed plus per-product diffs (capped; see diffs_truncated). |
| `rules_apply` | Write | Apply a feed's rules to its products and persist the resulting changes. Needs write:products as well as write:rules. |
